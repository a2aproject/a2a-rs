# SDK examples

Run commands from the workspace root. Each client discovers its server's agent
card and exercises JSON-RPC, REST, and gRPC.

## Hello World

In two terminals:

```sh
cargo run -p examples --bin helloworld-server
cargo run -p examples --bin helloworld-client
```

HTTP listens on port 3000 and gRPC on 50051. The client demonstrates unary and
streaming messages, task lookup/listing, cancellation, and subscriptions.

For TLS, run `helloworld-tls-server` and `helloworld-tls-client` instead. They use
ports 3443 and 50052 and certificates generated by `examples/build.rs`. The client
trusts the generated CA.

## Live messages (A2A 1.1)

In two terminals:

```sh
cargo run -p examples --bin live-server
cargo run -p examples --bin live-client
```

HTTP listens on port 3001 and gRPC on 50053. To choose other listening addresses:

```sh
cargo run -p examples --bin live-server -- 127.0.0.1:4001 127.0.0.1:50054
cargo run -p examples --bin live-client -- http://127.0.0.1:4001
```

The live client runs the same conversation over all three bindings:

1. `send_live_message` opens an exchange with `start`. Its first event supplies
   the task ID; the executor emits `Working` and waits on `ctx.inputs.recv()`.
2. `live.sender.send_message` sends `hello` to that task while the executor is
   running. The downlink announces the client message and the echoed response.
3. `pause` produces `InputRequired`, then the executor returns. The task and live
   exchange remain open.
4. `resumed` invokes the executor again for the same task. The message that
   starts this invocation is in `ctx.message`; further input is in `ctx.inputs`.
5. `finish` produces `Completed`, closing the downlink.

`live.events` carries task updates for every binding. HTTP sends subsequent input
as individual requests and returns task receipts; gRPC writes input on the duplex
stream. The executor and conversation code are shared across these bindings.
The client reports errors with a nonzero exit status and bounds each conversation
to 30 seconds.

See [the executor and conversation](src/live/mod.rs), [server](src/live/server.rs),
and [client](src/live/client.rs).

## Tests

```sh
cargo test -p examples --all-targets
```

Tests need permission to bind local sockets. `live_example_e2e` launches the actual
live server on ephemeral ports, checks persisted state and event ordering for each
binding, and runs the live client binary through all three conversations. The
existing suites cover task generations, live exchange edge cases, transports,
and push delivery.
